# Images

Everything here was learned by getting it wrong once.

## Before you capture anything

**Check the template renders the column you are about to fill.**

Setting `image` and `image_dark` on the featured project uploads two files,
writes two `media` rows, updates D1, and changes the page by zero pixels. The
featured panel in `src/pages/index.astro` renders `featured_logo`, the title and
`body_html`, and a comment in that file says outright that it "has no screenshot,
so its weight has to come from scale and space rather than from an image".

Ordinary project cards further down *do* render `image` and `image_dark`. Read
the template, not the column list.

## Aspect ratios that actually apply

| Slot | Shape | Source |
|---|---|---|
| Post hero | 1200x630, landscape | `blog/[slug].astro` hardcodes those attributes |
| Project card | around 1400x783 | `index.astro` `work__shot` |
| OG share card | 1200x630 | generated by `scripts/gen-og.mjs` |
| Body image | any, scales | global `img { max-width:100%; height:auto }` |

A 628x1280 phone screenshot in the hero slot renders at full column width and
about twice the column height. That is not a styling nitpick, it swamps the page.

## Composing portrait screenshots

Phone screenshots are the most compelling evidence for a messaging or bot post,
and the wrong shape for every slot. Compose them into one landscape figure.

The recipe that worked, using `sharp` from the site's `node_modules`:

- Lay frames side by side in narrative order. What it does, then the input and
  output, then the decision point.
- 36px gutters and 36px padding.
- Background `#12100e`, the site's own dark token. Screenshots of a dark app sit
  on it cleanly, and it reads as intentional in both site themes.
- Crop an on-screen keyboard off before composing, then `extend` that frame back
  to the common height so all panels stay top-aligned.
- Three 628x1280 frames give roughly 2028x1352, which is 1.5:1. Good as a body
  figure. Still not a share card; see below.

## Leak check, every time

Look at the image. Do not ingest an image you have not looked at.

- API keys, tokens, credential names
- customer and prospect names, phone numbers, email addresses
- open browser tabs and bookmark bars
- notification badges revealing private content
- filesystem paths that expose a client's directory

An n8n canvas is usually safe because node names are not secrets, but check the
sticky notes and any visible URL parameter.

## Alt text

Required, enforced, and not a formality. These images are the only evidence on a
portfolio page that the work exists, so an empty alt is a project with no content
for anyone using a screen reader.

Describe **the frame**, not the project. "The RABT Labs homepage, headlined X,
beside a mocked-up Instagram direct message at 23:04 in which..." rather than
"RABT Labs logo".

Per-image alt is supported with sidecar files: drop `light.txt` beside
`light.png` and `ingest` uses it.

## Ingesting

```bash
npm run ship:ingest -- --id <ledger-id> --alt "..."                 # whole folder
npm run ship:ingest -- --id <ledger-id> --file <path> --alt "..."   # one file
```

Use `--file` when the folder holds raw source frames you do not want uploaded
individually, such as three phone screenshots you have already composed.

`ingest` reproduces the site's own key format exactly,
`YYYY/MM/<slug>-<8hex>.webp`, so an image uploaded here is indistinguishable from
one uploaded through the admin. The admin media library lists it and its delete
button works on it.

Expect webp at quality 82 to land 80 to 90 percent smaller than the PNG.

## Share cards

Check the convention before choosing. Nineteen of twenty posts set `og_image` to
a relative `/assets/og/<slug>.png`, the themed card generated at build time.

A real screenshot loses to the themed card as a share image, even though it wins
on the page. Feeds crop to about 1.91:1, so a 1.5:1 composite gets clipped top
and bottom, and three phone screens are illegible at feed size anyway. The themed
card carries the title in brand type and is built at exactly 1200x630.

The fallback chain is `og_image || hero_image || /assets/og/<slug>.png`, so a
post with a hero and no explicit `og_image` shares its hero. If that hero is a
dense workflow canvas, set `og_image` explicitly.

The themed card only exists after a build, so a post published without a deploy
needs one before pointing at it.

## Capture quirks, measured

Two things make headless captures of this site lie, and both are fixed in
`ship/bin/capture.mjs`. Know them anyway, because they make a screenshot
untrustworthy as evidence.

**Lazy loading.** Every project image carries `loading="lazy"` and none of them
load in headless Chrome. Scrolling the document first, the usual advice, changed
nothing: 0 of 7 images had a non-zero `naturalWidth` before the scroll and 0 of 7
after. Flipping the attribute to `eager` loaded 7 of 7.

**Scroll-driven reveals.** `.settle-in` uses `animation-timeline: view()`, so an
off-screen element photographs at its first keyframe. The context now requests
`prefers-reduced-motion: reduce`, which the stylesheet already guards that rule
behind. Worth knowing: the `settle` keyframe deliberately never touches opacity,
so a real visitor with reduced motion still sees the image.

**Even with both fixed**, a very tall `--selector` capture still showed an empty
frame near the bottom for an image that was demonstrably live. Verify with
`curl`, not with a screenshot.
